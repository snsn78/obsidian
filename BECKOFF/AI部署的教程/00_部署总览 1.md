## 当前机器缺失的关键依赖

这几个项目里，`tree-sitter`、Rust MSVC 工具链、Python native wheel 构建都需要 C/C++ 编译工具。

当前检查结果：

- 未找到 Visual Studio Build Tools。
- 未找到 Windows SDK 的 `kernel32.lib`。
- npm 安装报错：`You need to install the latest version of Visual Studio including the Desktop development with C++ workload.`
- pip 安装 tree-sitter 语法包报错：`Microsoft Visual C++ 14.0 or greater is required.`
- Docker CLI 存在，但 Docker Desktop daemon 没启动。

## 必须补装的东西

最推荐安装：

1. Visual Studio Build Tools 2022
2. 组件选择：
   - `Desktop development with C++`
   - MSVC v143 x64/x86 build tools
   - Windows 10/11 SDK
   - CMake tools for Windows 可选

安装后重启 Hermes / Git Bash，再验证：

```bash
export PATH="$HOME/.cargo/bin:$PATH"
cargo --version
rustc --version
npm --version
find '/c/Program Files (x86)/Windows Kits' -name kernel32.lib | head
```

如果能看到 `kernel32.lib`，说明 Rust MSVC 和 node-gyp 的基础链接库已经具备。

## 推荐使用顺序

1. 先用 `plc-st-review`：最容易转化成 AI Agent 工具，用来检查 `.st` 代码风险。
2. 再用 `tree-sitter-iec61131-3-st`：负责把 ST 代码解析成语法树。
3. 再用 `truST Platform`：完整 PLC 工作区，包含 LSP、Runtime、Debug、Agent API。
4. 最后用 `rusty`：ST 编译器路线，依赖更重，但适合作为 AI 生成代码后的编译验证器。

## 给 AI Agent 的组合方式

```text
用户需求
  -> AI 生成 Structured Text
  -> tree-sitter 解析结构
  -> plc-st-review 静态检查
  -> rusty/truST 编译或诊断
  -> 输出修复后的代码和审查报告
```
