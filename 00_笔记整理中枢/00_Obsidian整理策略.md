# Obsidian 整理策略

> 目标：把现在的 Obsidian 从“资料堆”整理成“学习 + 项目 + 输出”的工作台。先不大规模移动旧文件，先建立入口、规则、模板和迁移顺序，再分批处理。

补充诊断：

- 根目录直接有约 `230` 个文件，绝大多数是截图、PDF、JPG、Canvas，说明入口层噪音过高。
- `.git` 约 `115 MB`，`.obsidian` 约 `36 MB`，`.smart-env` 约 `4.9 MB`，真正的 Markdown 笔记只是很小一部分。
- 备份目录 `__backlink_backup__`、插件安装备份、重复附件、未命名 `.base` 文件，都应纳入归档而不是日常内容区。
- 多个旧笔记无一级标题，少量空笔记存在，说明不仅要整理目录，也要统一笔记骨架。
- Canvas 引用和 Markdown 引用都要在移动附件前检查，不要直接用资源管理器大搬家。

最明显的问题：

1. 根目录有大量 `Pasted image ...png`，约 186 个，导致首页一打开就像垃圾桶。
2. 主题目录混用：`硬件学习/电赛` 里同时有题目、AI 建议、K230 问题、MSPM0 代码提示词、机械结构，项目和知识混在一起。
3. Canvas 很多但缺统一入口，图谱价值没有被串起来。
4. 备份目录和当前目录有重复文件名，例如 `05-实战篇.md`、`00_部署总览.md`、`QuickAdd 使用记录.md` 等，搜索时容易混淆。
5. Markdown 数量不算多，真正问题不是“太多”，而是“入口、命名、附件、状态”没有规则。

## 2. 总体整理原则

采用“项目制 + 领域库 + 知识卡片 + MOC 首页”的混合方案，不建议纯 PARA，也不建议纯卡片盒。

原因：

- 你的笔记很明显围绕真实项目展开：电赛、石总手柄、Hermes、BECKOFF、未来 NVH 项目。
- 你也有长期学习领域：硬件、AI、算法、数学。
- 你已经大量使用 Canvas，适合用 MOC 和 Canvas 做总控，而不是只靠文件夹。

一句话规则：

> 正在做的放项目，长期学的放领域，能复用的沉淀成知识卡片，原始资料统一进资料库，过期的进归档。

## 5. 命名规范

### 文件夹命名

使用数字前缀控制顺序，只给一级目录加数字：

```text
00_中枢
01_项目
02_领域
03_知识卡片
04_资料
05_日记
06_模板
90_归档
```

二级目录用中文主题名，不必全加数字，避免越整理越重。

### 笔记命名

推荐格式：

```text
主题-具体对象.md
项目名-问题或结论.md
板卡名-外设或功能.md
```

例子：

```text
K230-I2C通讯.md
MSPM0G3507-天猛星引脚.md
电赛-小球运动过程理解.md
Hermes-工具调用机制.md
```

避免：

```text
新建文档.md
整理一下.md
问题.md
感觉可以照抄的段落.md
```

如果确实是临时内容，放到 `05_日记` 或项目的 `00_Inbox`，不要直接塞进知识目录。

## 7. 标签规范

标签不要无限发散，先定 5 类：

| 标签前缀 | 用途 | 示例 |
|---|---|---|
| `#project/` | 项目 | `#project/电赛`、`#project/石总手柄` |
| `#area/` | 长期领域 | `#area/硬件`、`#area/AI` |
| `#hardware/` | 硬件对象 | `#hardware/k230`、`#hardware/mspm0` |
| `#tool/` | 工具 | `#tool/hermes`、`#tool/obsidian` |
| `#status/` | 状态 | `#status/todo`、`#status/done` |

注意：文件夹负责“位置”，标签负责“跨目录检索”。例如 `K230` 既能出现在硬件领域，也能被电赛项目引用，不要复制两份，用链接和标签连接。

## 8. 首页 MOC 设计

MOC 就是地图页，不负责塞所有内容，只负责告诉你“从哪里进入”。

首页应包含：

1. 当前正在推进的项目
2. 长期学习领域
3. 最近需要整理的 Inbox
4. 常用模板
5. 常用 Canvas 图谱
6. 最近一周任务

推荐入口：[[01_首页MOC]]

## 9. Canvas 使用策略

你已经有 49 个 Canvas，这其实是优势。建议 Canvas 分三类：

| Canvas 类型 | 用途 | 例子 |
|---|---|---|
| 项目路线图 | 任务阶段、模块关系、交付路线 | 电赛项目路线图、石总手柄链路 |
| 知识地图 | 概念之间怎么连 | K230 总图、Hermes 能力图 |
| 故障排查图 | 问题、原因、验证、解决方案 | K230 黑屏排查、ADB 连接排查 |

规则：每张 Canvas 必须链接到一个 MOC 或项目首页，否则以后会变成孤岛。

## 10. 附件治理策略

当前根目录最大的问题是截图过多。

### 新附件规则

在 Obsidian 设置里建议：

```text
Files & Links → Default location for new attachments → In the folder specified below
Attachment folder path → 04_资料/图片/剪贴图片
```

### 旧附件迁移规则

不要直接手动拖动根目录 `Pasted image*.png`。原因：Markdown 里可能有 `![[Pasted image ...png]]` 引用，直接移动会断图。

正确顺序：

1. 先用脚本扫描哪些图片被引用、哪些没被引用。
2. 被引用的图片移动到 `04_资料/图片/剪贴图片` 后同步改 Markdown 链接。
3. 未引用的图片移动到 `04_资料/图片/待识别`。
4. 一个月后确认没用，再归档或删除。

## 11. 每周维护流程

每周只做 30 分钟，不要搞成大工程。

```text
周日整理 30 分钟：
1. 清空根目录新截图
2. 清空项目 Inbox
3. 每个活跃项目只更新一个“下一步”
4. 把 1-3 条高价值内容沉淀成知识卡片
5. 检查孤立 Canvas 是否挂到 MOC
```

## 12. 迁移优先级

### 第一优先级：入口和附件

- 建立 `00_笔记整理中枢`
- 设置首页 MOC
- 设置新附件默认目录
- 后续截图不再进根目录

### 第二优先级：活跃项目

- `硬件学习/电赛` → `01_项目/电赛`
- `石总项目` → `01_项目/石总项目`
- 每个项目创建一个 `项目首页.md`

### 第三优先级：长期领域

- `硬件学习/K230`、`MSPM0G3507`、`LVGL` 整到 `02_领域/硬件学习`
- `AI_Learning` 整到 `02_领域/AI与Agent`
- `BECKOFF` 整到 `02_领域/PLC与BECKOFF`

### 第四优先级：归档和去重

- `__backlink_backup__` 放入 `90_归档`
- 重复文件只保留当前版本，备份版本不参与搜索入口
- 根目录散落 PDF、JPG、MP4 归入 `04_资料`

## 13. 不建议做的事

1. 不建议一次性全库重命名，容易断链接。
2. 不建议把所有东西都塞进 PARA 的 `Resources`，会重新变乱。
3. 不建议把 Canvas 当笔记正文替代品，Canvas 负责关系，Markdown 负责结论。
4. 不建议靠标签替代文件夹，标签多了比文件夹更乱。
5. 不建议删除 `.smart-env`、`.obsidian`、`__backlink_backup__`，除非确认备份和插件状态。

## 14. 最终效果

整理完成后，你的 Obsidian 应该像这样工作：

```text
我现在要做电赛 → 进 01_项目/电赛/电赛项目首页.md
我想查 K230 怎么用 → 进 02_领域/硬件学习/K230/K230-MOC.md
我想复习 PID → 进 03_知识卡片/硬件/PID-控制直觉.md
我只是临时记一句 → 进 05_日记/YYYY-MM-DD.md
我想看整体关系 → 打开对应 Canvas
```

核心标准：

> 10 秒内能找到入口，30 秒内能找到相关资料，3 分钟内能知道下一步做什么。
